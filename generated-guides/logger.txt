Q: logger 패키지가 뭐야?

A: logger는 Flutter/Dart 프로젝트에서 로그를 더 예쁘고 보기 좋게 출력해주는 작고 사용하기 쉬운 패키지야. 디버깅할 때 정말 유용하거든! 복잡한 로그 메시지를 보기 좋게 정리해주고, 에러 발생 시 스택 트레이스까지 깔끔하게 보여줘서 문제점을 파악하는 데 큰 도움을 줘.

   난이도: 초급
   예상 학습 시간: 5분

Q: 설치는 어떻게 해?

A: logger 패키지를 설치하는 건 아주 간단해. Flutter 프로젝트의 `pubspec.yaml` 파일에 dependencies 섹션에 추가해주면 돼.

────────────────────────────────────────────────────────────────────────
dependencies:
  flutter:
    sdk: flutter

  logger: ^1.1.0  # 최신 버전을 사용하려면 pub.dev에서 확인해보세요!
────────────────────────────────────────────────────────────────────────

그 다음 터미널에서 `flutter pub get` 또는 `dart pub get` 명령어를 실행하면 자동으로 다운로드되고 설치될 거야.

Q: logger 패키지를 어떻게 사용하기 시작하면 돼?

A: logger 패키지를 사용하려면 먼저 Logger 객체를 생성해야 해. 가장 기본적인 방법은 다음과 같아.

────────────────────────────────────────────────────────────────────────
import 'package:logger/logger.dart';

var logger = Logger();

void main() {
  logger.d('이건 디버그 로그야!');
  logger.i('이건 정보 로그야.');
  logger.w('조심해! 이건 경고 로그야.');
  logger.e('앗! 에러가 발생했어!');
}
────────────────────────────────────────────────────────────────────────

이렇게 Logger 객체를 만들고 나면 `d` (debug), `i` (info), `w` (warning), `e` (error), `wtf` (what a terrible failure) 같은 메서드를 사용해서 원하는 로그를 출력할 수 있어.

Q: logger 패키지의 주요 기능은 뭐가 있어?

A: logger 패키지는 여러 가지 유용한 기능들을 제공하는데, 몇 가지 핵심적인 것들을 알려줄게.

1.  Pretty Printing: 로그 메시지를 색상별로 구분하고, 메소드 이름, 시간 정보 등을 보기 좋게 표시해줘. 이걸로 로그를 한눈에 파악하기 쉬워져.
2.  Customizable Output: 로그를 콘솔뿐만 아니라 파일 등 다른 곳으로도 보낼 수 있도록 설정할 수 있어. 필요에 따라 로그 형식을 커스터마이징하기도 좋지.
3.  Error Handling with Stack Traces: 에러가 발생했을 때, 에러 메시지와 함께 해당 에러가 발생한 코드의 스택 트레이스까지 상세하게 보여줘. 디버깅 시간을 엄청나게 단축시켜줘.
4.  Log Levels: 디버그, 정보, 경고, 에러 등 다양한 로그 레벨을 지원해서, 어떤 종류의 로그인지 명확하게 구분할 수 있게 해줘. 이를 통해 필터링도 용이해져.
5.  Method Count Control: 스택 트레이스에서 보여줄 메소드 개수를 조절할 수 있어. 너무 많은 정보가 부담스럽다면 줄여서 볼 수도 있지.

Q: logger 패키지를 사용하다가 자주 발생하는 에러가 있다면 뭐가 있을까?

A: logger 패키지 자체에 복잡한 에러가 자주 발생하지는 않지만, 몇 가지 주의할 점이 있어.

1.  `pubspec.yaml` 오타 또는 잘못된 버전: `pubspec.yaml` 파일에 `logger` 패키지 이름을 잘못 쓰거나, 존재하지 않는 버전을 지정하면 `pub get` 과정에서 에러가 발생할 수 있어. 항상 정확한 패키지 이름과 최신 버전을 확인하는 게 중요해.
2.  `print` 함수와의 혼동: Flutter/Dart에서는 기본적으로 `print` 함수도 로그를 출력하는 데 사용되잖아. `logger` 패키지를 사용하면서 `print` 함수와 `logger` 메서드를 혼용하다 보면 어떤 로그가 어디서 온 건지 헷갈릴 수 있어. `logger`를 사용하기로 결정했다면, 가능한 `logger` 메서드만 사용하는 것이 깔끔해.
3.  비동기 작업에서의 로그 누락: 비동기 작업(async/await)을 할 때, 로그가 예상치 못한 시점에 출력되거나 누락될 수 있어. 비동기 작업의 각 단계마다 로그를 찍어보면서 흐름을 추적하는 것이 중요해.

Q: logger 패키지를 실무에서 더 잘 활용할 수 있는 팁이 있다면 알려줘.

A: 물론이지! logger 패키지를 실무에서 더 효과적으로 사용하는 몇 가지 팁을 알려줄게.

1.  로그 레벨별로 관리하기: 모든 로그를 `logger.d`로만 찍기보다는, 디버깅 시에만 필요한 정보는 `d`, 일반적인 정보는 `i`, 주의가 필요한 부분은 `w`, 심각한 에러는 `e` 등으로 명확하게 구분해서 사용해. 이렇게 하면 나중에 로그를 볼 때 훨씬 효율적이야.
2.  `PrettyPrinter` 옵션 활용하기: `PrettyPrinter`에는 `methodCount`, `errorMethodCount`, `lineLength`, `colors` 등 다양한 옵션이 있어. 예를 들어, `methodCount: 0`으로 설정하면 스택 트레이스에서 메소드 정보를 숨겨서 로그를 더 간결하게 만들 수 있어. 프로젝트의 스타일에 맞게 옵션을 조절해보자.

────────────────────────────────────────────────────────────────────────
var logger = Logger(
  printer: PrettyPrinter(
    methodCount: 0, // 메소드 개수 0개로 설정
    errorMethodCount: 5, // 에러 발생 시 메소드 개수 5개까지 표시
    lineLength: 120, // 로그 줄 길이
    colors: true, // 색상 사용 여부
    printEmojis: true, // 이모티콘 사용 여부
  ),
);
────────────────────────────────────────────────────────────────────────

3.  에러 로깅 시 에러 객체 함께 전달하기: 에러가 발생했을 때 `logger.e`에 문자열 메시지만 전달하는 것보다, 실제 에러 객체를 `error` 파라미터에 함께 전달하면 더 많은 정보를 얻을 수 있어.

────────────────────────────────────────────────────────────────────────
try {
  // 에러를 발생시키는 코드
  throw Exception('데이터를 불러오는 데 실패했습니다.');
} catch (e, stackTrace) {
  logger.e('데이터 로딩 중 에러 발생', error: e, stackTrace: stackTrace);
}
────────────────────────────────────────────────────────────────────────

이렇게 하면 에러 메시지뿐만 아니라 스택 트레이스까지 깔끔하게 로그로 남겨주기 때문에 문제 해결에 매우 도움이 될 거야.

Q: logger 패키지에서 `PrettyPrinter`는 꼭 써야 해?

A: `PrettyPrinter`를 꼭 사용해야 하는 건 아니야. `Logger` 객체를 만들 때 `printer` 옵션을 지정하지 않으면 기본적으로 `ConsolePrinter`가 사용되는데, 이것도 로그를 출력하는 데에는 문제가 없어. 하지만 `PrettyPrinter`를 사용하면 로그 메시지가 훨씬 보기 좋게 색상도 입혀지고, 메소드 정보나 시간까지 깔끔하게 정리되어서 디버깅할 때 훨씬 편리해. 그래서 많은 개발자들이 `PrettyPrinter`를 선호하는 편이야.

Q: 여러 개의 Logger 인스턴스를 만들어도 괜찮아?

A: 응, 여러 개의 `Logger` 인스턴스를 만들어도 괜찮아. 특정 상황에 맞는 설정을 가진 `Logger`를 따로 만들어서 사용할 수 있거든. 예를 들어, 일반적인 로그는 `PrettyPrinter`를 사용하고, 파일에만 기록되는 별도의 로거를 만들 수도 있고, 디버그 로그는 많이 찍지만 릴리즈 버전에서는 로그 출력을 최소화하고 싶을 때 로그 레벨을 다르게 설정한 `Logger` 인스턴스를 사용할 수도 있지.

────────────────────────────────────────────────────────────────────────
import 'package:logger/logger.dart';

var logger = Logger(); // 기본 설정

var debugLogger = Logger(
  printer: PrettyPrinter(methodCount: 2),
);

var releaseLogger = Logger(
  printer: PrettyPrinter(methodCount: 0, colors: false), // 릴리즈에서는 간결하게
);

void main() {
  logger.i('일반 정보 로그');
  debugLogger.d('디버그 전용 로그');
  releaseLogger.w('릴리즈에서도 볼 수 있는 경고');
}
────────────────────────────────────────────────────────────────────────

이렇게 상황에 맞춰 `Logger` 인스턴스를 다르게 설정해서 사용하면 코드 관리가 더 용이해질 수 있어.

Q: logger 패키지로 로그를 파일에 저장할 수도 있어?

A: 네, logger 패키지는 기본적으로 콘솔에 로그를 출력하지만, `LogOutput`을 커스터마이징하여 파일이나 다른 저장소로 로그를 보낼 수도 있어. 이를 위해서는 `LogOutput` 클래스를 상속받는 자신만의 클래스를 만들고, `output` 메서드를 구현해야 해.

────────────────────────────────────────────────────────────────────────
import 'dart:io';
import 'package:logger/logger.dart';

class FileOutput extends LogOutput {
  final File file;

  FileOutput(this.file);

  @override
  void output(OutputEvent event) {
    for (var line in event.lines) {
      file.writeAsStringSync('$line\n', mode: FileMode.append);
    }
  }
}

void main() async {
  var file = File('my_log.txt');
  var logger = Logger(
    output: FileOutput(file),
    printer: PrettyPrinter(),
  );

  logger.i('이 로그는 파일에 저장됩니다.');
  logger.e('에러 로그도 파일에 저장됩니다.');
}
────────────────────────────────────────────────────────────────────────

위 예시처럼 `FileOutput` 클래스를 만들어서 `Logger` 생성 시 `output` 파라미터에 전달하면, 로그가 `my_log.txt` 파일에 저장될 거야.

Q: logger 패키지를 사용하면 앱 성능에 영향을 많이 줄까?

A: logger 패키지는 기본적으로 성능에 큰 영향을 주지 않도록 설계되었어. 하지만 몇 가지 고려할 점이 있어.

1.  로그 양: 너무 많은 양의 로그를 계속해서 출력하면 당연히 성능에 약간의 영향을 줄 수 있어. 특히 디버그 레벨의 로그는 개발 중에만 사용하고, 릴리즈 빌드에서는 로그 레벨을 조정하거나 로그 출력을 완전히 비활성화하는 것이 좋아.
2.  파일 로깅: 로그를 파일에 계속 기록하는 경우, 디스크 I/O 작업이 발생하므로 콘솔 로깅보다는 성능에 조금 더 영향을 줄 수 있어. 이 역시 릴리즈 버전에서는 신중하게 사용해야 해.

따라서 개발 중에는 `PrettyPrinter`를 활용하여 상세한 로그를 확인하고, 릴리즈 빌드에서는 로그 레벨을 높이거나 `LogOutput`을 사용하지 않는 방식으로 최적화하는 것이 일반적인 방법이야.

Q: logger 패키지의 `wtf`는 언제 사용하는 거야?

A: `wtf`는 "What a terrible failure"의 약자로, 정말 심각하고 예상치 못한 오류가 발생했을 때 사용하도록 고안된 로그 레벨이야. 일반적인 `Error` 레벨(`e`)보다 더 치명적인 상황을 나타낼 때 사용한다고 생각하면 돼.

예를 들어, 앱이 더 이상 정상적으로 작동할 수 없는 상태에 이르렀거나, 복구 불가능한 심각한 버그가 발생했을 때 `wtf` 레벨로 로그를 남길 수 있어. 이 로그는 특별히 강조되어 표시되거나, 특정 환경에서는 알림을 발생시키는 용도로 활용될 수도 있지. 하지만 일상적인 디버깅이나 에러 처리에는 `e` 레벨을 사용하는 것이 더 일반적이야.

────────────────────────────────────────────────────────────────────────
void handleCriticalError() {
  try {
    // 매우 심각한 오류가 발생했다고 가정
    throw StateError('앱의 핵심 기능이 손상되었습니다.');
  } catch (e, stackTrace) {
    logger.wtf('치명적인 오류 발생!', error: e, stackTrace: stackTrace);
  }
}
────────────────────────────────────────────────────────────────────────

Q: logger 패키지를 사용하면 Flutter 개발이 훨씬 쉬워질까?

A: 맞아! logger 패키지를 잘 활용하면 Flutter 개발이 훨씬 수월해질 수 있어. 특히 복잡한 UI나 비동기 로직이 얽혀 있는 앱을 개발할 때, 각 단계마다 로그를 남겨두면 문제의 원인을 빠르게 파악하고 해결하는 데 큰 도움이 돼.

단순히 `print`만 사용하는 것보다 훨씬 구조화되고 보기 좋은 로그를 얻을 수 있어서, 코드를 따라가거나 버그를 추적하는 데 드는 시간을 크게 줄여줄 거야. 마치 개발자를 위한 친절한 안내등 같은 역할을 한다고 생각하면 돼!
